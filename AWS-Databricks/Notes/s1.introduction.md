# Apache Spark → Databricks → Databricks Access — Summary in Order

## 1. What is Apache Spark?

**Apache Spark** is a distributed processing engine used for:

* Data engineering
* Batch processing
* Stream processing
* Machine learning

It runs on a **distributed cluster of computers**.

Spark provides multiple capabilities through one framework:

| API / Capability     | Purpose                          |
| -------------------- | -------------------------------- |
| Spark SQL            | SQL-based processing             |
| DataFrame APIs       | Batch/data processing            |
| Structured Streaming | Stream processing                |
| MLlib                | Machine learning                 |
| GraphX               | Graph processing                 |
| RDD APIs             | Low-level distributed processing |

Spark supports **Scala, Java, Python and R**.

# 3. Spark Core vs Higher-Level APIs

Spark Core provides **RDD APIs**.

RDD APIs are low-level and available in:

* Scala
* Java
* Python
* R

But developers generally use higher-level APIs instead:

```text
Spark Core / RDD
       ↓
 ┌─────┴────────────────────────┐
 │                              │
Spark SQL                  DataFrame API
 │
Structured Streaming
 │
MLlib
 │
GraphX
```

The main idea is that higher-level APIs hide much of the complexity of distributed processing.

### 3. Unified platform

One framework supports:

```text
SQL
Batch
Streaming

```

### 4. Open source

Apache Spark is open source.

### 5. Large ecosystem

Many companies and tools integrate with Spark.

# 5. What Apache Spark Is NOT

This is a very important interview concept.

**Spark is powerful, but Spark itself is not a complete enterprise data platform.**

The lecture identifies several capabilities that Spark does not provide by itself.

### Missing capabilities

| Requirement                             | Apache Spark |
| --------------------------------------- | ------------ |
| Storage infrastructure                  | ❌            |
| Built-in ACID transactions              | ❌            |
| Robust centralized metadata catalog     | ❌            |
| Cluster management                      | ❌            |
| Complete enterprise automation platform | ❌            |

For example, Spark needs external storage:

```text
Spark
  │
  ├── S3
  ├── ADLS
  ├── HDFS
  └── GCS
```

Similarly, Spark itself doesn't provide a complete cluster-management platform.

Therefore:

> **Spark is a processing engine, not a complete enterprise data platform.**

# 14. Serverless Workspace Architecture

The lecture describes the serverless workspace using a **split-plane architecture**.

There are two major planes:

```text
             Databricks Workspace
                     │
          ┌──────────┴──────────┐
          │                     │
     Control Plane       Serverless Compute
                              Plane
```

## Control Plane

Contains/manages Databricks platform functionality such as:

* Web application
* Orchestration
* Unity Catalog
* Queries
* Code/workspace services

## Serverless Compute Plane

Responsible for:

* Launching compute
* Scaling compute
* Releasing compute
* Running workloads

The architecture separates the platform/control functionality from compute. 

---

# 15. Serverless Default Storage

In the basic serverless architecture, Databricks provides default storage.

For AWS, the lecture describes this as an S3 bucket associated with the Databricks environment.

Conceptually:

```text
Databricks Account
       │
       ├── Control Plane
       │
       ├── Serverless Compute
       │
       └── Default Storage
```

The concern is that an organization may want its data to remain under its own cloud account/control.

---

# 16. Serverless + Customer Cloud Storage

Databricks can also be connected to storage in the organization's own cloud account.

Example:

```text
Databricks
    │
    │ Cross-account role
    │ + permissions
    ↓
Customer AWS Account
    │
    └── S3 Bucket
```

The serverless compute plane can then read/write data in the customer's storage.

Main idea:

> **Separate the Databricks platform from the organization's data storage.**

The lecture describes this as decoupling the data from the platform. 

---

# 17. Classic / Hybrid Workspace

Some organizations need **dedicated clusters** rather than only serverless compute.

For that, Databricks provides:

**Classic / Hybrid Workspace**

It allows dedicated compute resources in the organization's cloud account.

Architecture:

```text
                 Databricks
                    │
             ┌──────┴──────┐
             │             │
       Control Plane   Serverless
                         Compute
             │
             │
       Cross-account roles
             │
             ↓
      Customer AWS Account
             │
       ┌─────┴──────────┐
       │                │
    S3 Bucket      Classic Compute
                      Cluster
```

---

# 18. Classic Workspace Compute

Classic/Hybrid workspace supports two compute types:

### Serverless compute

Managed by Databricks.

### Classic/dedicated compute

Runs dedicated clusters in the organization's cloud account.

For example:

```text
5 nodes
10 nodes
20 nodes
50 nodes
100 nodes
```

depending on requirements.

---

# 19. Two Important Cross-Account Permissions

In the classic/hybrid architecture, the lecture explains two major permission relationships.

### 1. Storage access

Allows Databricks compute to access the customer's S3 bucket.

```text
Databricks
    ↓
Cross-account role
    ↓
S3
```

### 2. Compute/EC2 access

Allows the Databricks control plane to manage EC2 resources:

* Create instances
* Delete instances
* Scale up
* Scale down
* Manage clusters

```text
Databricks Control Plane
          ↓
Cross-account role
          ↓
EC2 / Dedicated Cluster
```

So remember:

```text
Classic / Hybrid
       │
       ├── Storage role → S3
       │
       └── Compute role → EC2
```

# 20. Serverless vs Classic/Hybrid

| Feature                | Serverless                         | Classic / Hybrid               |
| ---------------------- | ---------------------------------- | ------------------------------ |
| Serverless compute     | ✅                                  | ✅                              |
| Dedicated clusters     | ❌                                  | ✅                              |
| Customer cloud storage | Can be configured                  | Required for workspace storage |
| Control plane          | Databricks                         | Databricks                     |
| Compute management     | Databricks                         | Databricks                     |
| Custom cluster control | Limited                            | ✅                              |
| Cross-account roles    | For customer storage if configured | Storage + compute              |
