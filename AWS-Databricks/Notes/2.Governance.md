# Data Mart – Databricks

## 1. Overview

A **Data Mart** is a curated, business-focused layer containing data required for a specific business domain or analytical use case.

In this project, the Data Mart is built on **Databricks + Delta Lake + Unity Catalog** and provides business-ready datasets for reporting, dashboards, and analytics.

```text
Raw Data
   │
   ▼
Bronze
   │
   ▼
Silver
   │
   ▼
Gold
   │
   ▼
Data Mart
   │
   ├── BI Dashboards
   ├── Reports
   └── Analytics
```

---

## 2. Objective

The Data Mart provides:

* Business-ready datasets
* Optimized analytical queries
* Consistent business definitions
* Aggregated metrics
* Controlled access through Unity Catalog
* Data lineage and governance
* Easy consumption by BI tools

## 6. Data Flow

### Step 1 – Ingestion

Source systems:

```text
Application DB
API
Kafka
Files
Cloud Storage
```

Data is initially landed in S3.

```text
Source
  │
  ▼
S3 Raw
```

### Step 2 – Bronze

Raw data is converted into Delta tables.

```text
S3 Raw
  │
  ▼
Bronze Delta
```

Bronze should preserve the source information with minimal transformation.

### Step 3 – Silver

Data is cleaned and standardized.

Typical operations:

* Remove duplicates
* Handle nulls
* Validate schema
* Standardize data types
* Clean invalid records
* Join reference data
* Apply business rules

```text
Bronze
   │
   ▼
Silver
```

### Step 4 – Gold

Business-level transformations are performed.

Examples:

```text
Daily sales
Monthly revenue
Customer lifetime value
Product performance
Store performance
```

```text
Silver
   │
   ▼
Gold
```

### Step 5 – Data Mart

The Data Mart exposes the datasets required by a particular business domain.

```text
Gold
 │
 ▼
Sales Data Mart
 │
 ├── fact_sales
 ├── dim_customer
 ├── dim_product
 └── dim_date
```

## 8. Example SQL

Create a dimension:

```sql
CREATE TABLE prod.mart.dim_customer
(
    customer_id BIGINT,
    customer_name STRING,
    city STRING,
    state STRING,
    customer_segment STRING
)
USING DELTA;
```

Create a fact table:

```sql
CREATE TABLE prod.mart.fact_sales
(
    sale_id BIGINT,
    customer_id BIGINT,
    product_id BIGINT,
    store_id BIGINT,
    date_id DATE,
    quantity INT,
    unit_price DECIMAL(12,2),
    discount DECIMAL(12,2),
    total_amount DECIMAL(12,2)
)
USING DELTA;
```

## 9. Example Business Query

Monthly revenue:

```sql
SELECT
    YEAR(date_id) AS year,
    MONTH(date_id) AS month,
    SUM(total_amount) AS revenue
FROM prod.mart.fact_sales
GROUP BY
    YEAR(date_id),
    MONTH(date_id)
ORDER BY
    year,
    month;
```

Revenue by product category:

```sql
SELECT
    p.category,
    SUM(f.total_amount) AS revenue
FROM prod.mart.fact_sales f
JOIN prod.mart.dim_product p
    ON f.product_id = p.product_id
GROUP BY
    p.category
ORDER BY
    revenue DESC;
```

## 10. Data Quality

Data quality checks should be applied before data reaches the Data Mart.

Examples:

### Primary key validation

```sql
SELECT customer_id, COUNT(*)
FROM prod.mart.dim_customer
GROUP BY customer_id
HAVING COUNT(*) > 1;
```

### Null validation

```sql
SELECT COUNT(*)
FROM prod.mart.fact_sales
WHERE sale_id IS NULL;
```

### Negative sales validation

```sql
SELECT COUNT(*)
FROM prod.mart.fact_sales
WHERE total_amount < 0;
```

Quality failures should be logged and handled by the pipeline.

## 12. Sensitive Data

Sensitive columns should not automatically be exposed to all users.

Example:

```text
dim_customer

customer_id       → Public within domain
customer_name     → Internal
email             → Restricted
phone             → Restricted
```

Use appropriate Unity Catalog access controls, masking, filtering, or curated views where required.

## 14. Performance

For large Data Mart tables:

* Use Delta Lake
* Select only required columns
* Avoid unnecessary `SELECT *`
* Optimize joins
* Partition only when justified
* Use appropriate clustering/optimization techniques
* Avoid excessive small files
* Use incremental processing instead of full reloads where possible

Example:

```sql
SELECT
    customer_id,
    SUM(total_amount) AS revenue
FROM prod.mart.fact_sales
WHERE date_id >= '2026-01-01'
GROUP BY customer_id;
```

---

## 15. Incremental Processing

The Data Mart should preferably be updated incrementally.

```text
New Source Data
      │
      ▼
Bronze
      │
      ▼
Silver
      │
      ▼
Only New/Changed Data
      │
      ▼
Data Mart
```

Instead of:

```text
Delete everything
      ↓
Reprocess entire dataset
```

incremental processing reduces processing cost and execution time.
