# Databricks Workspaces + Notebook Debugging — Summary in Order

This explanation has **2 lectures**:

1. **Databricks Workspace overview**
2. **Debugging in Databricks notebooks**

---

# 1. Databricks Workspace — Introduction

## 1.1 Types of Databricks Accounts

The lecture uses two accounts:

```text
Databricks Free Account
        ↓
Serverless Workspace only

Databricks Paid/Premium Account
        ↓
Serverless Workspace
        +
Classic Workspace
```

The **serverless workspace in Free Edition and Premium Edition looks largely the same** from the user's perspective.

---

# 2. What Is a Databricks Workspace?

A Databricks workspace is essentially your:

* IDE
* Development environment
* Testing environment
* Debugging environment
* Collaboration platform

You use it to:

```text
Develop
   ↓
Test
   ↓
Debug
   ↓
Run
   ↓
Collaborate
```

The lecture describes it as the main place where a Data Engineering team works on Databricks projects.

---

# 3. Workspace Navigation

The most important part of the workspace UI is the **left-side navigation menu**.

Both serverless and classic workspaces contain mostly the same menus:

```text
Workspace
Recent
Catalog
Jobs
Compute
Discover
Marketplace
SQL
Data Engineering
AI/ML
```

So from a UI/functionality perspective:

```text
Serverless Workspace
        ≈
Classic Workspace
```

The major difference is **compute capability**.

---

# 4. Workspace Explorer

Clicking:

```text
Workspace
```

opens the workspace explorer.

You can organize work using folders.

Example:

```text
Home
 └── exercises
      ├── notebook1
      ├── notebook2
      └── notebook3
```

Both serverless and classic workspaces provide this capability.

---

# 5. Catalog

The **Catalog** section is where Databricks metadata is accessed.

The lecture associates this with **Unity Catalog**.

You will use it to work with things such as:

* Catalogs
* Schemas
* Tables
* Metadata

Both workspace types provide access to the catalog functionality.

---

# 6. Jobs and Pipelines

The **Jobs & Pipelines** area is used for:

* Creating jobs
* Monitoring job runs
* Creating pipelines
* Monitoring pipeline runs

Again, this functionality exists in both workspace types.

---

# 7. Main Difference — Compute

This is the key point of the workspace lecture.

### Serverless workspace

Primarily provides serverless compute.

### Classic workspace

Provides:

```text
Serverless Compute
        +
Dedicated/Classic Compute
```

So:

```text
Serverless Workspace
        ↓
Serverless Compute

Classic Workspace
        ↓
Serverless Compute
        +
Classic/Dedicated Compute
```

The lecture emphasizes that **classic workspace can also use serverless compute**.

---

# 8. Compute Menu Difference

### Serverless workspace

The compute menu contains options such as:

* SQL Warehouse
* Vector Search
* Apps
* Lakebase

### Classic workspace

It contains those plus:

* All-Purpose Compute
* Job Compute
* Pools
* Policies

The additional options are related to dedicated/classic compute.

# 11. AI/ML

The AI/ML section provides Databricks capabilities for:

* Artificial Intelligence

# 12. Workspace Settings

Both workspace types provide settings.

* Switch workspace

# 13. Workspace Summary

The important takeaway:

> **Workspace is the main development and collaboration environment.**

Most Databricks functionality is available in both workspace types.

The major difference is:

```text
Classic Workspace
    ↓
Supports dedicated/classic compute

Serverless Workspace
    ↓
Does not allow you to create dedicated classic clusters
```

# 14. Databricks Notebook — Context for Debugging

The debugging lecture uses a Databricks notebook containing a mixture of:

* Python
* PySpark
* DataFrame operations
* Variables

A notebook needs compute attached before the code can execute or be debugged.

---

# 15. Enable Notebook Debugger

Go to:

```text
Workspace Settings
    ↓
Developer
    ↓
Developer Editor Settings
    ↓
Python Notebook Interactive Debugger
```

The lecture checks that:

```text
Python Notebook Interactive Debugger = ON
```

---

# 16. Attach Compute to Notebook

Before running/debugging:

```text
Notebook
   ↓
Attach Compute
   ↓
Serverless / Available Cluster
```

The lecture attaches a serverless cluster.

Once attached, the notebook can execute code on that compute.

---

# 17. Create a Breakpoint

Suppose the notebook contains:

```python
df = ...
x = 20
y = 30
```

You can place a breakpoint on a line.

Conceptually:

```text
Code
 ↓
Breakpoint
 ↓
Start Debugging
 ↓
Execution pauses
```

---

# 18. Start Debugging

Place the cursor in the cell and select:

```text
Debug Cell
```

The debugger opens.

Two important areas appear:

### Variables

Shows variables available at the current execution point.

Example:

```text
df
x = 20
y = 30
```

### Debugger

Provides controls such as:

```text
Continue
Next Line
Step In
Step Out
Stop
```

---

# 19. Step Through Code

The debugger executes the code line by line.

For example:

```text
Line 1 → import
Line 2 → create DataFrame
Line 3 → define x
Line 4 → define y
```

At each breakpoint/step, you can inspect the current state.

---

# 20. Inspect Variables

When execution reaches:

```python
x = 20
```

the Variables panel shows:

```text
x → 20
```

After:

```python
y = 30
```

it shows:

```text
y → 30
```

The DataFrame also becomes visible as a variable.

---

# 21. Debugger Console

One particularly useful feature is the debugger console.

While paused, you can execute code based on the current state.

For example:

```python
print(x)
```

Output:

```text
20
```

Or inspect a Spark DataFrame:

```python
df.show()
```

You can therefore investigate the program **without modifying the actual notebook code**.

---

# 22. Inspect DataFrame During Debugging

Example:

```python
df.show()
```

The debugger console displays the DataFrame records.

This is useful for checking:

* Current DataFrame contents
* Variable values
* Intermediate results
* Whether transformations produced the expected data

---

# 23. Finish Debugging

Once debugging is complete:

```text
Continue Execution
       OR
Stop Debugging
```

Then:

* Remove breakpoints if no longer required.
* Disconnect/terminate compute when appropriate.

The lecture particularly emphasizes cost awareness when using paid environments.

```text
                    Databricks

              ┌──────────┴──────────┐
              │                     │
        Serverless WS          Classic WS
              │                     │
              │              ┌──────┴──────┐
              │              │             │
         Serverless       Serverless    Classic/
           Compute         Compute      Dedicated
                                         Compute
```

And inside either workspace:

```text
Workspace
   │
   ├── Workspace Explorer
   ├── Catalog / Unity Catalog
   ├── Jobs & Pipelines
   ├── SQL
   ├── Data Engineering
   ├── AI/ML
   └── Compute

                    ↓
                Run Code
                    ↓
              Debug if needed
```

## 🔥 Interview Points

| Topic                | Key Point                                                  |
| -------------------- | ---------------------------------------------------------- |
| Workspace            | Main Databricks IDE/collaboration environment              |
| Serverless Workspace | Uses serverless compute                                    |
| Classic Workspace    | Supports serverless + classic/dedicated compute            |
| Catalog              | Access to Unity Catalog metadata                           |
| Jobs/Pipelines       | Create and monitor workloads                               |
| Notebook             | Interactive environment for code, output and documentation |
| Debugger             | Allows breakpoints and step-by-step execution              |
| Variables            | Inspect current variable state                             |
| Debug Console        | Execute expressions while paused                           |
| Compute              | Required to execute/debug notebook code                    |

**One-line memory trick:**

> **Workspace = where you work; Compute = where your code runs; Notebook = where you write/run code; Debugger = where you inspect code execution.**
