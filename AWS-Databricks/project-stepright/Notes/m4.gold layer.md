# Gold Layer — Summary

The lecture covers the development of the **5 Gold reporting tables** for StepRite. Gold is where the cleaned Silver data is transformed into business-ready reports. 

The five reports are:

```text
1. Daily Revenue
2. Customer 360
3. Product Performance
4. Funnel Analysis
5. Fulfillment Health
```

---

## 1. Gold Daily Revenue

### Business requirement

Finance wants a trustworthy daily revenue report instead of manually stitched Excel reports.

Report dimensions:

```text
Revenue Date
Category
Region
```

Metrics:

```text
Gross Revenue
Discount
Net Revenue
```



### Source tables

Five datasets are required:

```text
Silver Order Items
Silver Orders
Silver Products
Silver Categories
Order Subtotals
```

Orders are SCD Type 2, so only the **current order record** is selected using:

```text
__END_AT IS NULL
```



### Important challenge — discount allocation

Discount exists at the **order level**, while revenue/line totals exist at the **order-item level**.

Therefore, discount must be distributed proportionally:

```text
Item Discount
=
(Item Line Total / Order Subtotal)
× Order Discount
```

Example:

```text
Order total = 1000
Discount    = 50

Item = 250
Allocated discount = 250/1000 × 50 = 12.5
```

This is one of the important Gold-layer business transformations. 

### Final aggregation

```text
Gross Revenue = SUM(line_total)

Discount = SUM(allocated_discount)

Net Revenue = Gross Revenue - Discount
```

Grouped by:

```text
Revenue Date
Category
Region
```

# 2. Gold Customer 360

### Business requirement

Marketing wants to understand:

* Valuable customers
* Customers who may be churning
* Customer lifetime value
* Number of orders
* Recency of last purchase

### Sources

Only two Silver tables are needed:

```text
Silver Customers
Silver Orders
```

Both are SCD Type 2.

So first:

```text
Customers → current records
Orders    → current records
```

Then aggregate orders by customer:

```text
Customer ID
    ↓
Total order value
Number of orders
Last order date
```

Finally join the order summary with customer information.

### Final report

```text
First Name
Last Name
Loyalty Tier
Lifetime Value
Number of Orders
Days Since Last Order
```

The key idea is:

```text
SCD2 tables
   ↓
Current records
   ↓
Aggregate orders by customer
   ↓
Join customer profile
   ↓
Customer 360
```

# 3. Gold Product Performance

### Business requirement

Merchandising wants to understand **sales velocity + current stock** rather than relying on stale reports.

### Sources

```text
Silver Order Items
Silver Products
Silver Inventory
```

### Step 1 — Calculate sales

From Order Items:

```text
GROUP BY product_id
```

Calculate:

```text
Units Sold
Revenue
```

### Step 2 — Get latest inventory

Inventory is **time-series data** coming from multiple warehouses.

Therefore, first find the latest inventory record for each:

```text
Product + Warehouse
```

Using a window function:

```text
PARTITION BY product_id, warehouse
ORDER BY snapshot_date DESC
```

Take:

```text
rank = 1
```

### Step 3 — Calculate current stock

After getting the latest record for each warehouse:

```text
GROUP BY product_id
SUM(quantity_available)
```

This gives current stock across warehouses.

### Step 4 — Calculate stock risk

Threshold:

```text
20
```

If:

```text
current_stock < 20
```

then:

```text
stock_risk = true
```

Final report:

```text
Product ID
Product Name
Brand
Units Sold
Revenue
Current Stock
Stock Risk
```

# 4. Gold Funnel Analysis

### Business requirement

Growth team wants to know:

> Which referral/channel converts users into purchases?

### Important problem

Around 50% of clickstream events don't have a `customer_id`.

If we build the report around customer ID, anonymous traffic would be lost.

### Solution: Session-level analysis

Use:

```text
session_id
```

instead of:

```text
customer_id
```

Because every event has a session.

### Step 1 — Determine session conversion

Group by:

```text
session_id
referrer
```

If the session contains a:

```text
purchase
```

event:

```text
converted = 1
```

Otherwise:

```text
converted = 0
```

### Step 2 — Aggregate by referrer

Calculate:

```text
Total Sessions
Converted Sessions
Conversion Rate
```

Formula:

```text
Conversion Rate
=
Converted Sessions / Total Sessions
```

Architecture:

```text
Clickstream
    ↓
Session ID
    ↓
Converted / Not Converted
    ↓
Group by Referrer
    ↓
Funnel Analysis
```

# 5. Gold Fulfillment Health

### Business requirement

Operations wants to know whether delivery commitments are being met.

The project assumes:

```text
SLA = 5 days
```

The desired report is:

```text
Order Date
Region
Delivered Orders
Orders Within SLA
SLA Compliance %
```

### Important limitation

There are 3 warehouses, but **orders don't contain warehouse ID**.

Therefore, the report cannot legitimately show warehouse-level fulfillment performance.

The lecture explicitly chooses **not to invent/fake warehouse attribution**.

### Step 1 — Get delivered orders

From current Silver Orders:

```text
__END_AT IS NULL
```

Then:

```text
order_status = delivered
```

### Step 2 — Calculate delivery time

```text
Days To Deliver
=
updated_at - order_date
```

### Step 3 — Check SLA

```text
Days To Deliver <= 5
        ↓
    Within SLA
```

Then aggregate:

```text
Delivered Orders
Within SLA Orders
```

And calculate:

```text
SLA Compliance
=
Within SLA Orders / Delivered Orders
```

# Final Gold Architecture

At the end, there are **5 Gold materialized views**:

```text
                    SILVER
                       │
        ┌──────────────┼───────────────┐
        ↓              ↓               ↓
  Gold Revenue    Customer 360   Product Performance
        │              │               │
        └──────────────┼───────────────┘
                       │
              Funnel Analysis
                       │
              Fulfillment Health
```

More practically:

```text
Silver
  │
  ├── Orders + Order Items + Products + Categories
  │                 ↓
  │          Gold Daily Revenue
  │
  ├── Customers + Orders
  │          ↓
  │     Gold Customer 360
  │
  ├── Order Items + Products + Inventory
  │          ↓
  │     Gold Product Performance
  │
  ├── Clickstream
  │          ↓
  │     Gold Funnel Analysis
  │
  └── Orders
             ↓
      Gold Fulfillment Health
```

The lecture uses **Databricks Materialized Views** for Gold reporting. The materialized view can use incremental refresh when possible and fall back to full refresh when necessary. 

## ⭐ Most important concepts to remember

| Gold report         | Main concept                                             |
| ------------------- | -------------------------------------------------------- |
| Daily Revenue       | **Order-level discount → proportional item allocation**  |
| Customer 360        | **SCD2 → current records → customer aggregation**        |
| Product Performance | **Latest inventory using window function**               |
| Funnel Analysis     | **Session-level attribution because of anonymous users** |
| Fulfillment Health  | **SLA calculation using delivery time**                  |

So the overall Medallion flow is now:

```text
Source
  ↓
Landing
  ↓
Bronze
  ↓
Bronze Quality / Quarantine
  ↓
Silver
  ↓
Business Rules
  ↓
Gold
  ↓
5 Business Reports
```

And **Gold is primarily about business-oriented aggregation and reporting**, rather than raw cleansing.
