# Silver Layer — File-Based Sources Summary

## 1. First: Decide how to handle the 4 file sources

There are 4 file-based sources:

| Source      | Nature                  | Silver approach |
| ----------- | ----------------------- | --------------- |
| Products    | Daily full snapshot     | **Auto CDC**    |
| Categories  | Daily full snapshot     | **Auto CDC**    |
| Clickstream | New events continuously | **Append-only** |
| Inventory   | Daily additive records  | **Append-only** |

### Products & Categories

Every day, the complete product/category snapshot is uploaded.

If we simply append:

```text
Day 1 → Products 1,2,3
Day 2 → Products 1,2,3
Day 3 → Products 1,2,3
```

we create duplicates.

Therefore:

```text
Products     → Auto CDC
Categories   → Auto CDC
```

### Clickstream & Inventory

These are treated as **additive/append-only** sources.

```text
Clickstream → Append
Inventory   → Append
```

No merge/Auto CDC is required.

The lecture's first design decision is therefore **snapshot sources use Auto CDC; additive sources use append-only flows**.

---

# 2. How can Auto CDC work without Debezium TSMS?

The file sources don't have:

```text
OP
TSMS
before
after
```

like the CDC sources.

But Bronze already adds:

```text
ingested_at
_source_file
```

Therefore, for Products and Categories:

```text
ingested_at
     ↓
used as Auto CDC sequence
```

So `ingested_at` provides the ordering information needed by Auto CDC.

# 4. Products → Auto CDC

Products are snapshots, so we use **Auto CDC**.

### Business rule

```text
retail_price > cost_price
```

Meaning the product should not have a retail price lower than/equal to its cost according to the project rule.

### Implementation pattern

Three main steps:

```text
1. Create source view
2. Create Silver streaming table
3. Create Auto CDC flow
```

Source:

```text
bronze_products_valid
        ↓
product_change_feed
        ↓
silver_products
```

The source view also converts `launch_date` to a date.

Auto CDC uses:

```text
Key       → product_id
Sequence  → ingested_at
```

And Bronze metadata fields such as:

```text
ingested_at
_source_file
is_quarantined
```

are not carried into the Silver business table.

---

# 5. Categories → Auto CDC

Categories are also daily snapshots.

Therefore:

```text
bronze_categories_valid
        ↓
categories_change_feed
        ↓
Auto CDC
        ↓
silver_categories
```

Again:

```text
Key       → category_id
Sequence  → ingested_at
```

There is **no Silver business rule specified for categories** in this lecture.

That's perfectly acceptable; not every table needs a business-quality rule.

---

# 6. Clickstream → Append-only

Clickstream is naturally append-only.

Every event is a new event:

```text
bronze_clickstream_valid
          ↓
    silver_clickstream
```

No Auto CDC or merge is required.

### Two business rules

#### Rule 1 — Purchase

If:

```text
event_type = purchase
```

then:

```text
order_id IS NOT NULL
```

#### Rule 2 — Product interaction

If:

```text
event_type = product_view
OR
event_type = add_to_cart
```

then:

```text
product_id IS NOT NULL
```

The Silver flow also converts:

```text
event_time → timestamp
```

and removes Bronze metadata fields that aren't needed in Silver.

---

# 7. Inventory → Append-only

Inventory is also treated as append-only.

Flow:

```text
bronze_inventory_valid
        ↓
   silver_inventory
```

### Business rules

#### Rule 1

```text
quantity_available =
quantity_on_hand - quantity_reserved
```

#### Rule 2

```text
quantity_reserved <= quantity_on_hand
```

The `snapshot_date` is converted to a date.

# 8. Final Silver Architecture

After implementing all four file sources:

```text
                    SILVER

Products ───────→ Auto CDC ─────→ silver_products
Categories ─────→ Auto CDC ─────→ silver_categories

Clickstream ────→ Append ───────→ silver_clickstream
Inventory ───────→ Append ───────→ silver_inventory
```

Together with the 3 CDC sources implemented previously:

```text
CDC Sources
───────────
Orders       → Silver Orders
Customers    → Silver Customers
Order Items  → Silver Order Items
                         ↓
                    Quarantine
```

So now **all 7 sources are represented in Silver**.

The lecture confirms the completed Silver layer contains products, categories, inventory, customers, orders, order items, and clickstream, with the required quality handling.

# Important Interview Takeaways

### 1. Why Auto CDC for Products/Categories?

Because they are **full daily snapshots**. Appending snapshots would create duplicates.

### 2. Why append-only for Clickstream?

Because each click is a **new event**, not an update to yesterday's event.

### 3. Why append-only for Inventory?

The project treats each daily inventory position as a new/additive record rather than an update to a previous position.

### 4. What is used as the sequence for file-based Auto CDC?

```text
ingested_at
```

because file sources don't have Debezium's `TSMS`. 

### 5. Final Silver decision

```text
Snapshot files → Auto CDC
Additive files  → Append-only
```

That's the **main concept to remember from this lecture**.
