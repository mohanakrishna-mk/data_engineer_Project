## StepRite Databricks Lakehouse — Summary

### 1. Project Goal

Build a **production-ready Databricks Lakehouse** for StepRite, an online footwear retailer, using:

* Medallion Architecture — **Bronze → Silver → Gold**
* Delta Lake
* Unity Catalog
* CDC
* Auto Loader
* Unit + integration testing
* Data quality as code
* Databricks Asset Bundles (DABs)
* CI/CD with production approval
* End-to-end pipeline 

### 2. Business Problems

StepRite has 3 major problems:

| Team          | Problem                                                | Required solution       |
| ------------- | ------------------------------------------------------ | ----------------------- |
| Finance       | Revenue report is manual, late and sometimes incorrect | **Daily Revenue**       |
| Marketing     | Can't easily identify valuable/churning customers      | **Customer 360**        |
| Merchandising | Inventory reorder decisions are based on stale reports | **Product Performance** |

Two additional analytics requirements:

* Growth → **Funnel Analysis**
* Operations → **Fulfillment Health**

## 3. Source Systems

There are **5 major source types**:

### Transactional databases

1. Order Management
2. Customer Management
3. Clickstream database

These cannot handle heavy analytical queries because they support live business transactions.

### File sources

4. Product catalog/categories → CSV
5. Inventory → daily CSV/Excel from 3 warehouses

### Main constraint

We need:

**Fresh data + no heavy load on production OLTP systems.** 

---

## 4. Ingestion Decisions

### For databases → CDC

Instead of querying OLTP directly:

**Debezium → CDC → flattened JSON → S3 → Databricks**

Debezium reads the database **change log**, rather than repeatedly querying production tables.

Benefits:

* Minimal impact on OLTP
* Near-real-time changes
* Captures INSERT / UPDATE / DELETE

The project assumes Debezium is already configured; the course starts from the **S3 landing zone**. 

### For files → Auto Loader

Use **Auto Loader** for:

* Products
* Categories
* Inventory
* JSON files arriving from CDC

Auto Loader provides:

* Incremental file discovery
* Schema inference
* Schema evolution
* Avoids processing the same file repeatedly

# 6. Medallion Architecture

### Bronze

Purpose: **store what actually arrived.**

* Raw
* Durable
* Replayable
* Allows rebuilding downstream pipelines

### Silver

Purpose: **make data trustworthy and usable.**

Examples:

* Clean data
* Validate data
* Handle CDC
* Build current/historical records
* SCD processing

### Gold

Purpose: **business-ready data marts.**

Five Gold outputs:

1. `daily_revenue`
2. `customer_360`
3. `product_performance`
4. `funnel_analysis`
5. `fulfillment_health`



---

# 7. Why Separate Gold Tables?

Don't create one giant table.

Each business domain has different:

* Refresh requirements
* Owners
* Business logic
* Failure impact

Therefore, create separate transformation pipelines/views for each business requirement.

# 8. Referential Integrity

Example:

```text
order_items.order_id
        ↓
orders.order_id
```

The project **does NOT enforce foreign keys during writes**.

Instead:

### Unity Catalog

Declare the relationship.

### Data Quality

Continuously monitor for orphan records.

```text
Foreign key declared
        ↓
Not enforced
        ↓
Data quality check
        ↓
Count orphan records
        ↓
Alert if count > 0
```

Reason: CDC streams can arrive asynchronously. An `order_item` might arrive before its parent `order`. 

---

# 9. Production Deployment

Use **separate production workspace**.

```text
Development
     ↓
CI/CD
     ↓
Manual Approval
     ↓
Production Workspace
     ↓
Production Unity Catalog
```

Nothing should directly reach production.

This protects production dashboards from untested changes.

## ⭐ Interview-Level Architecture in One Line

> **CDC/Auto Loader → S3 Landing → Unity Catalog Volume → Auto Loader → Bronze Delta → Silver Delta/SCD → Five Gold Data Marts → Orchestration → Testing/Data Quality → DAB + CI/CD → Production Workspace**

The key architectural reasoning is:

**CDC** solves freshness + OLTP load,
**Auto Loader** solves incremental file ingestion,
**Bronze/Silver/Gold** provides replayability + trustworthy transformations + business marts,
**Unity Catalog** provides governance,
**Testing/Data Quality** protects correctness, and
**DAB + CI/CD + approval** protects production.
